**Contract notes that Addendum A relies on** (recorded here as constraint 6 requires before a zod schema changes)

- **PRN-04 / B-3.** `TravelingTeacherResponse.TeacherName` is `string?` (`BusModule.cs:61`), but the app's `fleetBusSchema.traveling_teachers[].teacher_name` is `z.string()` (`src/data/http/transport.mappers.ts:30-32`). Once B-3 returns the field, a teacher with no `Users.Name` and no `Teachers.Name` would fail the whole fleet parse. The correct contract is nullable, so A5 makes it `.nullish()` and maps null to `''`.
- **PRN-04/05 / A-7.** Both `/transport/fleet` and `/transport/buses` already send `route_id` (captures `principal/PRN-04.json` and `PRN-05.json`). `fleetBusSchema` and `transportBusSchema` strip it, so A10 adds `route_id: z.string().nullish()`.
- **APR-01 / A-6.** `LeaveResponse.Priority` is sent (`principal/APR-01.json` `priority: "medium"`), but `leaveResponseSchema` has no `priority`. A15 adds it.
- **BUS-03 / A-8.** `Boardings.State` is free text, and the driver/staff app writes `dropped` (`TripService.cs:181`, `ValidBoardingStates = ["boarded", "absent", "dropped"]`). So the roster schema must accept `pending | boarded | absent | dropped`. A9 maps `dropped` to the app's `boarded`, which is **a decision to confirm at CHECKPOINT 2**.

**Scope decisions for the user**

- **SD-1 (STF-01, 🔒).** The teacher-side staff directory calls `GET /staff`, which is `school.principal` only, so it always returns 403 for teachers. Should teachers see non-teaching staff? If yes, give that one read route a teacher-readable policy (backend). **Security note:** "yes" widens authorization on an existing route (staff names, phones and roles become readable by every teacher); it is not an additive change. If no, apply A-9.
- **SD-2 (PRN-02).** What should "class total / present" mean on the principal attendance screen, which reads it as "N/M students"? Proposed default: `total` = active headcount (the same number as `/classes` `student_count`), `present` = distinct students marked present or late in any period that day. The alternative is to keep period-mark counts and relabel them in the app.
- **SD-3 (BUS-01).** `RouteStops` has **no `Time` column**. For any bus with a route, stop times are always null, and the teacher bus screen renders empty times. Is a per-stop time needed for routed buses? That would be a new column and migration, which is a feature. If not, A-8 alone makes the app show no time.
- **SD-4 (BUS-04).** `POST /bus/{id}/boarding` returns 409 `no_active_trip` unless a live trip exists. Teachers cannot start a trip, because `/transport/buses/{id}/trip/start` is principal-only. So the duty teacher's boarding save fails unless a driver or principal has started the trip. Is that the intended product flow?
- **SD-5 (ownership).** The following are gated only by `teacher.app` / `IsStaff`, with no per-teacher ownership. Is per-teacher ownership a product requirement? Until it is, none of these is a fix.
  - Any teacher can PATCH or DELETE any exam paper (EXM-05/06).
  - Any teacher can grade any paper (GRD-02).
  - Any teacher can edit any assignment (ASG-03).
  - Any teacher can change any student's photo (STU-03).
  - **Security concern:** any staff role (including every teacher) can read another user's payslips with `GET /payslips?user_id=` (PAY-01; the app does not send `user_id`).
- **SD-6 (ATT-05 vs ATT-06).** Daily roll-call writes `AttendanceRecords`. Every official number (student `attendance_pct`, principal KPIs, PRN-02) reads **only** `PeriodAttendanceRecords`. Daily roll-call feeds only the dashboard `attendance_today`. Should the app keep offering daily roll-call as a separate flow?
- **SD-7 (DSH-01, low).** `/dashboard/stats` is school-wide, not teacher-scoped: all students, all classes, and every per-student `Homework` row counted as a "pending assignment". Should it be teacher-scoped?

  - (1) `next_period` (`AcademicsRepositories.cs` `ClassSelectWithLiveCountAndNextPeriod` and `ListForTeacherAsync`) compares `upper(left(to_char(now() AT TIME ZONE 'UTC','DY'),3))` and `StartTime > to_char(now() AT TIME ZONE 'UTC','HH24:MI')`. Timetable times are school-local, as the code comment in `ListClassDayTimetableAsync` says. At 10:00 IST (04:30 UTC) period 1 (09:00) still counts as "next", and on an IST Monday before 05:30 the UTC day is still Sunday. The class docstring already admits this limitation. Fix B-1.
  - (2) `subject` is the class-level stored column. The seed sets "Mathematics" on both classes, so teacher B (Science) sees "Mathematics" on his Home class cards (`HomeScreen.tsx:102`, `ClassListCard.tsx:42`). The backend contract is correct: it is a class attribute. The app reads it as "my subject in this class", so the fix is app-side (A-1).
  - `student_count` is correct (live count; the stored column is 0).
- **STU-01.** The roster query matches students on Grade+Section **without** `Status='active'`, while `student_count` counts only active students. The two can diverge once a student is deactivated. There is no seed evidence, so no fix is proposed; this is a candidate follow-up.
- **ATT-06.** A denied period mark returns error code `forbidden`, while a denied roll-call returns `not_roll_call_teacher`. Both are 403. The app should key on the status, not the code.
- **PRN-01.** The contract matches (✅), but `kpis.students_present_pct` comes from the same `ResolveStudentTotalsAsync` (ReportingRepository.cs:208-222, used at L236-238) that B-2 changes. If B-2 lands, this KPI changes as well, so Task 13 must assert PRN-01 together with PRN-02.
- **PRN-04.** `FleetBus.stops` is parsed by `fleetBusSchema` but never rendered: neither FleetMap nor `FleetBusCard` reads it (the card uses only `stopCount`). It is effectively 💤 on the app side, so no fix is proposed for the missing `stops`. Only `traveling_teachers` (rendered in `FleetBusCard.tsx:82-103`) is a ⛔.
- **TT-01.** Categorised 🔀, not ⚠️: the backend returns exactly what it documents, and the app interprets the list as "my own periods".
  - `TimetableRepository.ListForTeacherAsync` deliberately includes every slot of a class where the caller is class teacher (documented as "this teacher's own").
  - `ScheduleScreen.cellFor` takes the first slot for a given day and period. For teacher A on Friday P2 there are two slots: IX-B Maths (hers) and IX-A Science (Bharat's). The order is `ORDER BY Day, Period` only, so which one shows is arbitrary.
  - P3 (English, Maya) also shows on her schedule.
  - The app already has `slotsTaughtByTeacher` (`lib/homeworkSubjects.ts`), so the fix is app-side (A-2) and the backend contract stays as documented.
- **EXM-01.** The exam's `status` is `draft` even though `published` is true. The seed did not set `Status`, so the column default applies. The app schema ignores `status`, so there is nothing to fix.
- **EXM-04 / EXM-05.**
  - The API accepts `status` only on update and `class_id` only on create. Extra JSON fields are silently ignored, so the app gets 201/200 and assumes the value was saved.
  - The backend alternative (additive `status` on `CreateExamPaperRequest`, `class_id` on `UpdateExamPaperRequest`) is possible, but the fix rule says to fix the app when the contract is correct.
- **GRD-02.** `dbo.grade_upsert` sets `"StudentName" = grade_upsert.StudentName` both on insert and in `ON CONFLICT DO UPDATE`. Every app save therefore stores or overwrites NULL, which also affects the student app's report card (`GET /grades?student_id`).
- **CHT-04.** The app sends only a free-text `name`/`role`. The server resolves the recipient by name unless `contact_kind`/`contact_id` are sent. This is not a contract mismatch (both fields are optional), but name matching is fragile. Recorded for Task 11.
- **APR-02.** `DecideLeaveAsync` does not validate the `status` value or require the request to still be pending. Recorded; no fix proposed.
- **PRN-06.** `dbo.busassignment_assign` handles the unique `(TenantId, TeacherUserId)` index with `ON CONFLICT DO UPDATE`, which moves the teacher. So assigning teacher B to DS-01 needs no unassign first, and it removes teacher A from DS-01. The service does not check that `teacher_user_id` is a teacher in the tenant.
- **HUB-01.** The payload shape matches. Not every write publishes an event: `PUT /grades` and exam-paper create/update/delete publish nothing, so those screens refresh only on refetch. Informational.
- **HUB-02.**
  - Principal-tier callers also join `transport-fleet:{tenant}` automatically and receive `fleet_update`, which the app does not subscribe to. That is harmless.
  - `JoinBus` returns `false` on denial. The app ignores the return value and keeps the bus in its `joined` set, so it never retries. Informational.
