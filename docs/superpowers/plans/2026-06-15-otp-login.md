# Mobile / Email OTP Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an inline OTP sign-in (mobile or email) below the existing password form on the login screen; the OTP step only "sends" if the identifier is already a registered account, otherwise it errors with "not registered".

**Architecture:** Extend `AuthRepository` with `requestOtp` / `verifyOtp` (mock looks the identifier up across the two seeded accounts; HTTP wires `/auth/otp/*` for parity). `AuthProvider` gains `requestOtp` and `signInWithOtp`, both reusing a shared `establishSession` helper. New `useRequestOtp` / `useVerifyOtp` hooks drive a small two-state OTP block on `LoginScreen`.

**Tech Stack:** React Native (Expo), TypeScript, @tanstack/react-query, Jest, Ionicons, expo-linear-gradient.

**Spec:** `docs/superpowers/specs/2026-06-15-otp-login-design.md`

**Run all tests with:** `npm test -- <path>` (Jest). Type-check with `npx tsc --noEmit`.

```ts
import type { AuthRepository, OtpChallenge } from '@/data/repositories/types';
import type { Store } from './store';
import { simulateLatency } from '@/lib/latency';
import { AppError } from '@/lib/errors';
import { seed, principalSession } from './seed';

const OTP_CODE = '123456';
const ACCOUNTS = [seed.session, principalSession];

const normalizeEmail = (s: string) => s.trim().toLowerCase();
const normalizePhone = (s: string) => s.replace(/\D/g, '');

function findAccount(identifier: string) {
  const raw = identifier.trim();
  if (raw.includes('@')) {
    const email = normalizeEmail(raw);
    return ACCOUNTS.find((a) => a.user.email.toLowerCase() === email);
  }
  const phone = normalizePhone(raw);
  if (!phone) return undefined;
  return ACCOUNTS.find((a) => normalizePhone(a.user.phone) === phone);
}

function maskEmail(email: string): string {
  const [name, domain] = email.split('@');
  return `${name.slice(0, 1)}••@${domain}`;
}

function maskPhone(phone: string): string {
  return `••••${normalizePhone(phone).slice(-4)}`;
}

export function mockAuth(store: Store): AuthRepository {
  return {
    async login(email) {
      await simulateLatency();
      if (!email) throw new AppError({ code: 'invalid', status: 400, message: 'Email required' });
      await store.setCurrentAccount(email);
      return store.session;
    },
    async refresh() {
      await simulateLatency();
      return store.session;
    },
    async me() {
      await simulateLatency();
      return store.session.user;
    },
    async logout() {
      await simulateLatency();
    },
    async requestOtp(identifier): Promise<OtpChallenge> {
      await simulateLatency();
      if (!identifier || !identifier.trim()) {
        throw new AppError({
          code: 'invalid',
          status: 400,
          message: 'Enter a mobile number or email',
        });
      }
      const account = findAccount(identifier);
      if (!account) {
        throw new AppError({
          code: 'not_found',
          status: 404,
          message: "This mobile or email isn't registered.",
        });
      }
      const isEmail = identifier.includes('@');
      return {
        channel: isEmail ? 'email' : 'sms',
        destination: isEmail ? maskEmail(account.user.email) : maskPhone(account.user.phone),
        devCode: OTP_CODE,
      };
    },
    async verifyOtp(identifier, code) {
      await simulateLatency();
      if (code !== OTP_CODE) {
        throw new AppError({ code: 'invalid', status: 401, message: 'Invalid code. Try again.' });
      }
      const account = findAccount(identifier);
      if (!account) {
        throw new AppError({
          code: 'not_found',
          status: 404,
          message: "This mobile or email isn't registered.",
        });
      }
      await store.setCurrentAccount(account.user.email);
      return store.session;
    },
  };
}
```

```ts
import type { AuthRepository } from '@/data/repositories/types';
import type { HttpClient } from '@/lib/httpClient';
import {
  toSession,
  toOtpChallenge,
  toUser,
  type SessionDTO,
  type OtpChallengeDTO,
} from './mappers';

export function httpAuth(http: HttpClient): AuthRepository {
  return {
    login: (email, password) =>
      http.post<SessionDTO>('/auth/login', { email, password }).then(toSession),
    refresh: (refreshToken) =>
      http.post<SessionDTO>('/auth/refresh', { refreshToken }).then(toSession),
    me: () => http.get<SessionDTO['user']>('/auth/me').then(toUser),
    logout: () => http.post<void>('/auth/logout'),
    requestOtp: (identifier) =>
      http.post<OtpChallengeDTO>('/auth/otp/request', { identifier }).then(toOtpChallenge),
    verifyOtp: (identifier, code) =>
      http.post<SessionDTO>('/auth/otp/verify', { identifier, code }).then(toSession),
  };
}
```

## Self-Review Notes

- **Spec coverage:** identifier accepts mobile or email (Task 2 `findAccount`, Task 7 field); lookup-before-send with "not registered" error (Task 2 + Task 7 step 7.2); fixed code `123456` (Task 2 `OTP_CODE`); reject wrong codes (Task 2 `verifyOtp`); inline placement below Sign In (Task 7 step 3); masked destination + demo-code hint (Task 2 masking + Task 7 UI); auth wiring via `establishSession` (Task 5); hooks (Task 6); HTTP parity (Tasks 3-4). All spec sections map to a task.
- **Type consistency:** `OtpChallenge` (camelCase `devCode`) defined in Task 1, mapped from `OtpChallengeDTO` (`dev_code`) in Task 3, consumed unchanged in Tasks 4-7. `findAccount` used identically in `requestOtp` and `verifyOtp`. `establishSession` signature `(s: Session) => Promise<void>` used by both `signIn` and `signInWithOtp`.
- **Deviation from spec:** the spec mentioned a "module-scoped pending map" to resolve the account at verify time. The plan instead re-runs the stateless `findAccount(identifier)` in `verifyOtp` (the UI always passes the identifier), which is simpler and avoids shared mutable state. Behavior is identical.
